## Efficiency and isolation

1. Reuse existing model integrity, sealed data, shader-byte and driver evidence
   only under their unchanged exact scope/current-boot gates. No reconversion,
   successful-file retransfer or redundant whole-model hash is scheduled.
2. Use read-only host metadata/trace/byte controls to reject impossible settings.
   Do not execute learned model inference on the host. Keep bulk preparation on
   the data disk and prepare one selected complete layout, not four model copies.
3. Reuse qualified compiler/objects and rebuild only affected application or
   overlay inputs. Bind current sources, link/import/SELF and failure-path checks.
4. Keep independent changes selectable and compare them separately. A candidate
   may provide bounded route metadata for later screening without per-expert
   logging. Metadata must fit the existing tracked heap.
5. Use fresh physical intents and exact ownership. Reuse the qualified small
   current-owner observation after current full startup integrity; do not repeat
   a large post-launch binary scan merely to rediscover an already bound owner.
6. A returned pre-GPU refusal follows the qualified ordinary-close/restoration
   path. Unknown I/O or GPU completion retains backing; no retry, force-close,
   GPU reset, reclaim or reserve reduction is permitted.
