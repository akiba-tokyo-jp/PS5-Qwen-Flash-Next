# Application-limit boundary audit

The owner requests an inventory of limits selected with unmeasured padding, measurement of their operating boundaries, and reconciliation of historically rejected candidates affected by those limits. A software refusal is not a hardware exhaustion result. Existing immutable case evidence is never rewritten or replayed.

Inventory the actual installed link and generated headers, rather than repository defaults alone. Separate OS observations/API limits, measured finite workload peaks, unmeasured application padding, test/evidence capacities, performance decisions and correctness/completion invariants. Record current value, source, provenance, demonstrated operating point, unknown boundary and affected candidate.

The first native scope is an isolated adaptive application-padding experiment on the original-GPU ten-request I/O comparison. Original CPU preparation and GPU initialization retain their existing predicates. Only positively completed model-load, context and inference boundaries can reduce application padding through256, observed OS reserved,128,64 and0 pages. The observed OS minimum remains mandatory. The OS reserved/minimum/target values are not written. Context preparation retains the previously observed41-page transient price; the separate unmeasured2-page rounding and64-page steady padding are measured separately by this scope. No I/O/GPU operation is replayed when a predicate changes. Original Direct/Flexible/CPU/ledger capacity checks, owner/source/format identity, fences, pending-resource retention, finite request count and ordinary close/restoration remain mandatory.

Record each phase's minimum observed free pages, effective application padding, number of predicates the legacy policy would reject, reductions and completed requests. A successful lower-padding lifetime demonstrates that the old threshold was unnecessarily restrictive for that measured scope; it does not establish a universal physical failure point or qualify a permanent production margin. If the observed OS floor cannot admit a next operation, preserve the returned failure, close ordinarily and restore production. Do not manufacture a physical exhaustion point by allocating until the console fails. Reboot remains unavailable.
