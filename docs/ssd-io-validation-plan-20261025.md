# Original-precision SSD I/O validation

> Historical completed initial screen. Later one-worker and palette/GPU screens also completed without a new production winner; see the [current plan index](plan-index.md). Router forecasting remains a separate unimplemented proposal.

The owner authorized this comparison after the 2026-10-25 research review.
Preserve the installed production SELF `ed4b360b...169d` and all rollback evidence.
Use the pinned cumulative-idle driver and keep persistent caches and CI disabled.
No consumed native case or failed call is replayed. No agents are used.

Status: initial codec, native delivery, continuous scheduling, packing and
router-capacity gates evaluated. No candidate was admitted for production.
See [results and remaining prerequisite distinctions](ssd-io-validation-results-20261025.md).

1. Screen independently implemented BF16 exponent/sign-mantissa separation with
   pinned BSD LZ4 and host Zstd on representative original matrices. Check every
   BF16 bit pattern, full restored bytes, bounded malformed-input refusal and
   whole delivery cost. Native input/output/exponent scratch must fit 8 MiB.
   Compare raw LZ4, exponent LZ4 and independent exponent shards. Host timings are
   a filter, not PS5 speed evidence. Keep original files and model layout intact.
2. For a viable codec, run a distinct CPU-only PS5 Direct-read/decode comparison
   over small separately owned immutable samples. Keep the real memory/session/
   descriptor/completion guards, original 8 MiB scratch and kernel reserves.
   Record raw/encoded read time, restoration, destination writes and complete
   digests. No native application publication or GPU operation is needed here.
3. Evaluate continuous delivery of known expert misses separately from the
   already-screened four-smaller-read variant. First identify empty-queue time
   with known work available. Preserve request count/owned-bank limits; improve
   completion-driven submission only if an observable gap exists.
4. Evaluate router lookahead against existing trace and capacity bounds. Do not
   repeat the rejected previous-token predictor. Predictions control transfer
   only; the original router selects every executed expert. Charge all forecast
   slots, read buffers and router state before claiming an admissible design.
5. Screen expert packing only on a small sidecar after its potential I/O savings
   exceed added gather/stream costs. Do not create another complete model copy.

Only a positive native delivery comparison admits optional full-model integration.
That requires a distinct artifact, original-precision output/token/route checks,
matched decode/TTFT measurement, actual native frames, positive source/GPU/model
retirement, ordinary close and full installed/restoration readback. Preserve the
currently fastest production version unless a complete candidate is faster.
