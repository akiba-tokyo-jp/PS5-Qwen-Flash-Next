## Measurement and adoption rules

Record samples and observed maxima, variation, repetitions, firmware/artifact
identity and the phase they describe. A finite sample is not a universal future
memory minimum. Selected additional margins receive their own field and rationale.
Direct payload capacity is checked separately from measured VM mapping overhead;
Flexible quota, virtual address spans and physical resident bytes stay distinct.

An outer screen authorizes only its next priced phase. Actual allocation return
status and subsequent native resource observations determine continuation.
Each new phase preserves a completed-boundary early-exit path. Unknown opaque
completion retains ownership and gets a distinct failure record; elapsed time
does not establish cancellation. Whole original identity/integrity and normal
exact-owner close/restoration remain part of every applicable title lifetime.

The result ledger records successful comparisons, measured regressions,
inconclusive variability, returned resource/API failures and missing dependencies
separately. A policy refusal alone supplies no physical-impossibility conclusion.
Speed adoption requires a reproducible improvement in the relevant complete path
with exact required output and resource retirement, rather than a fixed 5% cutoff
or a source-only ratio represented as model tokens/s.

The plan is complete only after every listed stage has its actual evidence and
every old item has an updated disposition. Implementation, native execution,
speed and adoption stay distinct. A host build or report does not close a pending
native comparison.
